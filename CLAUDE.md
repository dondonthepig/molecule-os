## i18n architecture (do not change without explicit instruction)

- Single resolved dictionary singleton at `src/lib/i18n/index.ts` (`dict`), backed by `src/locales/zh-TW.json` (primary, `defaultLocale`) and `src/locales/en.json` (parity-checked via `en satisfies Dictionary`, not yet wired to any switcher).
- **No `[locale]` URL routing.** The whole app renders in `defaultLocale = "zh-TW"` only.
- `dict` is imported directly into both Server and Client Components — safe because the JSON has no secrets.
- System CJK font fallback stack in `globals.css` (`--font-sans`), not a loaded webfont.

## Chemistry feature architecture (shared by Bond Explorer + Molecule Library; the template for future Phase 2 pages)

- Structural/technical data (ids, 3D coordinates, real Pauling electronegativity values, real molecular weights, correct-answer indices) lives in `src/lib/chemistry/*.ts` — never in JSX. `molecules.ts` is the single source of 3D structural data for **every** chemistry feature — extend it (add molecules/bond kinds) rather than forking it. `bond-types.ts` and `quiz-data.ts` are Bond-Explorer-specific; `functional-groups.ts` and `molecule-library-data.ts` are Molecule-Library-specific metadata layered on top of the same `molecules.ts` ids (kept separate so neither feature's data shape constrains the other).
- All display text (names, explanations, quiz questions/options, UI labels, category/functional-group/geometry names) lives in the dictionary (`dict.bondExplorer.*`, `dict.moleculeLibrary.*`) in both locale files, referenced from components by id — same single-dictionary rule as the rest of the app. Each feature keeps its own self-contained `molecules` copy block (e.g. a molecule's name appears in both `dict.bondExplorer.molecules` and `dict.moleculeLibrary.molecules` where both features use it) rather than cross-referencing another feature's namespace.
- **`BondVisualization`/`BondVisualizationScene` (`src/components/chemistry/bond-visualization*.tsx`) is the one shared 3D viewer** — do not fork a second Three.js scene. It's dynamically imported with `ssr:false` + a pulsing-gradient loading fallback (mirrors `hero-molecule.tsx`). Extended for Molecule Library with backward-compatible optional props (`showLabels`, `showBonds`, `renderMode: "ballAndStick"|"spaceFilling"`, `enablePan`, `autoRotate`) — all default to Bond Explorer's original behavior, so its call site needed zero changes. Bond-type/molecule switches remount an inner `<group key=...>` rather than using imperative refs, keeping the API prop-driven — follow this pattern for any new reset/replay-style interaction rather than adding refs across the dynamic-import boundary.
- Respect `usePrefersReducedMotion()` in any new 3D/animated component — freeze particle motion and auto-rotate when true.
- Cross-feature navigation (e.g. "explore this molecule's bonds" → Bond Explorer, "view in library" → Molecule Library) is done via a query param (`?bondType=`, `?molecule=`) read through a small `useSearchParams()` wrapper component under a `Suspense` boundary in the target page — this preselects state without either feature importing the other's components, and without breaking static prerendering. Follow this exact pattern (new wrapper + prop on the existing workspace component) for any future cross-feature deep link — don't add `useSearchParams` directly to a workspace component itself.
- `molecule-library-data.ts`'s `MoleculeCategory` union is the canonical category list shared by Molecule Library's filters and Organic Chemistry's category map — extend it in place (as done for `ether`/`amide`) rather than creating a parallel category system.
- Organic Chemistry's `organic-chemistry.ts` cross-references `functional-groups.ts` and `molecule-library-data.ts` by id rather than redefining functional-group or molecule data; its own dictionary content covers only category-level structure/property/reaction prose that doesn't exist elsewhere.

## Visual design system

- **UI color palette lives in `src/app/globals.css` as named tokens**: `--molecule-black` (#010101), `--molecule-navy` (#243b67), `--molecule-navy-dark` (#2f4678), `--molecule-blue` (#0571cc), `--molecule-ice` (#91c9ed), `--molecule-light` (#b9ddf4), `--molecule-soft` (#7fb6e5). These are the canonical names — reference them, never hardcode these hex values in a new component.
- **`--color-brand-blue`/`-cyan`/`-purple` (+`-dim` variants) are aliases onto the `--molecule-*` tokens**, kept only so every existing `text-brand-cyan`, `border-brand-blue/40`, `from-brand-blue ... to-brand-purple` etc. className in the app repaints automatically — there is no actual purple in the palette; `brand-purple` resolves to navy (the darkest of the three accent stops). Prefer the existing `brand-*` utility classes for new UI chrome (nav, cards, buttons, badges) rather than introducing new token names — the alias layer is exactly what makes global re-theming possible without touching every component.
- Semantic shadcn tokens (`--primary`, `--accent`, `--ring`, `--sidebar-primary`, `--chart-1..5`) are also wired to `--molecule-*`, so `Button`'s default variant, focus rings, and any future chart component pick up the palette automatically.
- **THE CRITICAL RULE: UI colors and scientific (CPK) atom colors are two separate systems — never mix them.** `ATOM_COLORS` in `molecules.ts` holds standard CPK colors (H=white/light-gray, C=dark gray, O=red, N=blue, Na=yellow, Cl=green, Fe=metallic gray) and must never be changed to match a UI accent. Conversely, bonds in `BondVisualizationScene` are neutral/metallic gray (not brand-colored), while *explanatory overlays* (shared-electron-pair particles, ionic transfer particles, the ionic attraction glow, the hydrogen-bond line, the metallic electron sea) intentionally use the ice-blue/medium-blue palette, since they represent an explanatory highlight rather than a physical atom.
- A component that explicitly labels atoms with element symbols (e.g. `interactive-demo-section.tsx`'s mini Na⁺/Cl⁻/H "demo" visuals) is depicting real chemistry and must use CPK colors like the real chemistry engine — even though it lives on the landing page. Purely abstract decoration with no element identity (the hero's decorative ring/tail 3D "molecule" in `hero-molecule-scene.tsx`/`molecule-data.ts`, the reduced-motion `StaticMoleculeGlyph` glyph, `feature-visuals.tsx`'s icons, the hero's testimonial-style avatar dots) is fair game for the UI palette. When in doubt: does it have an element label a chemistry-literate user would recognize? If yes, CPK; if no, brand palette.
- SVG/`fill="white"` atom-label text needs a dark outline (`stroke="black" strokeWidth="3" strokeOpacity="0.55" paintOrder="stroke"`) to stay legible against light CPK atom colors (hydrogen is now near-white, sodium is yellow) — this bit the redesign once already in `atom-visualization.tsx`/`interactive-demo-section.tsx`; the 3D scene's `Html` labels already handle this via a CSS `text-shadow` and didn't need the fix.
- Background is `#010101` (true black) at the `:root`/`.dark` level; `.light` theme deliberately keeps its own light background — the redesign's dark palette is not forced onto the light theme, only its accent colors (primary/ring/chart) are shared.
